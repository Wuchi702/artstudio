# Signature Interior

Русскоязычное портфолио «Архив света». Next.js App Router, React, TypeScript, GSAP, локальные Cormorant Garamond и Manrope. Цвет, сетка, адаптивные режимы и состояния собраны в CSS. SIGNATURE INTERIOR — временное название из брифа.

## Запуск

Требуется Node.js 22.18+ и npm.

```sh
npm ci
npm run dev
```

Откройте `http://localhost:3000`. Для production-сборки выполните `npm run build`, затем `npm start`. Проверки выполняются командами `npm run lint`, `npm run typecheck` и `npm test`. HTTP smoke запускается на работающей локальной сборке командой `node tests/smoke.mjs http://127.0.0.1:3000`.

## Страницы и контент

- `/` — главная с избранными работами, подходом и форматами работы.
- `/projects` — архив с фильтрами, адрес сохраняет выбранную категорию.
- `/projects/[slug]` — проект с перестраиваемыми секциями, галереей и переходом дальше.
- `/about`, `/services`, `/contact` — подход, форматы работы и заявка.
- [data/site.ts](data/site.ts) — имя, словесный знак, проверенные контакты, фотография, биография, услуги и принципы. Установите `available: true` для подтверждённых услуг.
- [data/editorial.ts](data/editorial.ts) — заголовки и тексты страниц.
- [data/projects.ts](data/projects.ts) — изображения и записи проектов. Добавьте файлы в `public/images/`, укажите `id`, уникальный URL-безопасный `slug`, название, фотографии и известные факты. Порядок задаётся массивом `sections`, появление на главной — `featured`. Используйте `status: 'realized'` для подтверждённого объекта и `status: 'concept'` для концепции.

В текущем архиве три концепции. Материалы и промпты перечислены в [паспорте визуализаций](docs/visual-assets.md). [Художественные направления и референсы](findings.md).

## Настройка формы и SEO

Скопируйте `.env.example` в `.env.local` и задайте следующие значения.

| Переменная | Назначение |
|---|---|
| `SITE_URL` | Публичный origin сайта, включая схему. Используется для canonical, Open Graph, sitemap, robots и проверки Origin в форме. Укажите перед сборкой и сохраните в runtime. |
| `CONTACT_WEBHOOK_URL` | HTTPS-адрес принимающего сервиса. Форма активируется, когда настроены адрес и `SITE_URL`. |
| `CONTACT_WEBHOOK_TOKEN` | Опциональное значение серверного заголовка `Authorization: Bearer …`. |

Обработчик отправляет JSON с полями `name`, `email`, `phone`, `property`, `area` и `comment`. `area` передаётся числом или `null`, `property` принимает `apartment`, `house`, `commercial` или `other`. Принимающий сервис должен вернуть HTTP 2xx после принятия заявки. Ошибка, редирект или таймаут отображаются без подтверждения получения. Форма требует JavaScript. На публичном хостинге ограничьте частоту обращений к `POST /api/contact` на входном прокси в соответствии с квотой принимающего сервиса.

Без настройки форма сообщает о недоступности приёма заявок. Сайт отдаёт noindex и запрещает обход до задания публичного адреса. Для реального сайта заполните подтверждённые контакты, подключите приёмник и проверьте фактическую доставку через публичный origin.

## GitHub Pages

Workflow `.github/workflows/pages.yml` проверяет код, создаёт статический экспорт и публикует его через GitHub Actions. Локальный экспорт для сайта проекта собирается командой:

```sh
GITHUB_PAGES=1 SITE_URL=https://wuchi702.github.io NEXT_PUBLIC_PAGES_BASE_PATH=/artstudio npm run build
```

Результат находится в `out/`. На Pages форма показывает состояние недоступности. Для приёма заявок доступна серверная сборка Next.js с webhook.
